## Reuse decisions and remaining boundaries

- Retain binary UUID lookup, precomputed prefixes, one runtime, reused buffers
  and allocation-free rounding. XML and polling checks do not add work to the
  binary value callback. The new mismatch guard reads the client's public metrics
  snapshot around commands; that API includes locks and a close-code-map clone,
  so it is not advertised as zero-cost. A narrow upstream accessor/result would
  remove this overhead.
- Do not copy the relay's MQTT ingestion, base64 payload mapping, VI command
  sending or unpublished topic-map endpoint into this sensor exporter. They
  serve different data contracts. Do not copy Python/PyO3 packaging or
  architecture-specific tuning that narrows CPU compatibility.
- **Client API improvement still advisable:** expose per-response correlation
  status and verify the full target after encrypted fallback decryption. The
  bridge can inspect plaintext UUIDs and the published mismatch counter, but
  cannot independently decrypt an opaque echoed `LL.control`. A same-verb,
  wrong-target encrypted fallback may not increment that counter. Responses
  without `control` still rely on FIFO, as in the client. The current safeguards
  do not constitute complete independent request/response identity verification.
- **Startup cancellation:** the owned handshake is allowed to finish/fail under
  the upstream timeouts, then an unclaimed client requests cleanup. The test
  proves cleanup after the delayed reply resumes. It does not prove immediate
  token revocation while a peer is unresponsive or after process/runtime exit.
  A cancellation-safe upstream `connect()` with explicit shutdown ownership
  would be the cleaner library-level solution.
- **Line protocol policy:** genuine string values retain the existing Rust CR/LF
  escaping instead of reproducing Python's raw embedded newlines, which conflict
  with record framing. Numeric/text namespaces and optional invalid-value/unit
  processing are intentional migration policies, documented in the README.
  See the [Influx line-protocol specification](https://docs.influxdata.com/influxdb/v2/reference/syntax/line-protocol/).
- **Sparse/unnamed poll outputs:** the old handler only visited extra outputs
  when `output0` existed and could turn its byte-string fallback into the field
  name `b'Subdefault'`. Rust processes sparse `output*` members and uses
  `Subdefault`; an explicitly supplied numeric `nr = 0` becomes `0`. These are
  deliberate corrections, not exact reproduction of Python truthiness and
  byte-string formatting. Ordinary named AQ/Q/etc. outputs keep their names.
- No exactly-once claim: UDP and MQTT QoS 0 cannot confirm storage; TCP retries
  can replay a partially delivered batch; the queue is memory-only. No live
  Miniserver/database run, long-duration CPU/RSS measurement, historic data
  conversion or release publication is part of this offline audit.

### Performance check after the final fixes

Same macOS ARM64 host and release profile. Three alternating before/after runs
of saved binaries, seven samples per run; table values are the median of the
three run medians. Builds finished before timing. Allocation counting is separate
from the timed loop. The baseline is the implementation immediately before this
final audit, not the initial unoptimized port.

| Workload | Before | After | Allocations before → after |
| --- | ---: | ---: | ---: |
| Round a number to five decimals | 41 ns | 40 ns | 0 → 0 |
| Two-field JSON | 0.368 µs | 0.358 µs | 6 → 6 |
| 33-field JSON | 6.457 µs | 6.367 µs | 45 → 45 |
| 2,605,334-byte XML export | 21.136 ms | 21.164 ms | 468,978 → 470,165 |

Timing remains at the preceding level; these small differences are not claimed
as a new speedup. XML allocation count increases by about **0.25%** and allocated
bytes from 25,772,043 to 25,841,997 per configuration parse. Retaining the unit
replacement buffer avoids an additional trim-copy allocation. The JSON envelope
retains its borrowed `control`, adding 24 allocated bytes per sample but no new
allocation. These are parser/route-construction measurements, not whole-process
CPU or polling round-trip measurements; the client metrics snapshots are outside
this benchmark. All performance gains from the earlier DOM/XML changes are
retained at this measurement resolution.

Reproduction commands are in [performance.md](performance.md). The synthetic
golden corpus is `tests/fixtures/legacy_line_protocol.json`; it contains no
private device data and was generated with legacy `influxdb-client` 1.50.0.
Real export contents, room names and credentials are not
copied into the report or checked-in fixtures.
